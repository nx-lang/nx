## NX Logo

![The NX logo](nx-logo.svg)

The NX logo is the letter N followed by an X made of two angle brackets: a closing `>` and an
opening `<`, set tip to tip. The X is markup, which is what NX is for. The brackets carry two
colors so that they read as two brackets and not as a plain X: deep blue on the `>`, gold on the
`<`. The N stays neutral, since the brackets carry the meaning.

This folder is the single source for the logo. Every file here is generated by `generate.mjs`,
which also writes the copies the website and the VS Code extension use (see [Where the logo is
used](#where-the-logo-is-used)).

### Files

| File | Use it for |
| --- | --- |
| `nx-logo.svg` | The logo on light backgrounds. The default. |
| `nx-logo-on-dark.svg` | The logo on dark backgrounds. |
| `nx-logo-mono-black.svg`, `nx-logo-mono-white.svg` | One-color printing, embossing, and places that can't show color. |
| `nx-mark.svg`, `nx-mark-on-dark.svg` | The bracket X alone, where the N would be redundant or too small. |
| `nx-icon.svg` | The app icon: the X on an ink tile. Favicons, extension and app icons, avatars. |
| `nx-icon-light.svg` | The app icon on a white tile, for dark surroundings where an ink tile disappears. |
| `png/nx-icon-*.png` | The app icon at 512, 256, 180 (Apple touch icon), 128, 32 and 16 pixels. |
| `png/nx-logo-1200.png`, `png/nx-logo-on-dark-1200.png` | The logo as images, for places that don't take SVG. |
| `png/nx-social-card.png` | The 1200×630 card shown when a page of the website is shared. |

The SVGs are drawn as shapes with no text, so they need no fonts and look the same everywhere.
They are cropped tight to the drawing: add space around them where you place them.

### Logo colors

These are settled: they are the colors the logo is drawn in.

| Color | Hex | Used for |
| --- | --- | --- |
| Deep blue | `#1F4FE0` | The closing bracket `>`, on light backgrounds |
| Gold | `#C98500` | The opening bracket `<`, on light backgrounds |
| Ink | `#16171C` | The N, text, dark backgrounds, the app icon tile |
| Paper | `#F5F4EF` | Light backgrounds, the N on dark backgrounds |
| Blue on dark | `#4D78FF` | The closing bracket on dark backgrounds |
| Gold on dark | `#FFB020` | The opening bracket on dark backgrounds |

The two bracket colors are lighter on dark backgrounds so they stay visible: blue on dark has a
4.6:1 contrast ratio against ink. Gold on white is only 3.1:1, which is enough for a logo but not
for text or thin lines, so don't use gold for text on light backgrounds.

### Proposed brand colors

> **Status: proposal, not yet applied or reviewed.** The website still uses the violet accent of
> the placeholder logo (`sites/website/src/styles/custom.css`). Try these colors on the website,
> look at the result in both themes, then replace this section with the final decisions.

The logo colors say which bracket is which. Brand colors are a different question: what each
color does across the website, the docs, the playground and the editor. The proposal gives each
color one job:

| Color | Hex (light / dark theme) | Proposed job |
| --- | --- | --- |
| Deep blue | `#1F4FE0` / `#4D78FF` | The primary color: links, buttons, the selected sidebar item, focus rings. |
| Gold | `#C98500` / `#FFB020` | Highlights only, used sparingly: a "new" badge, a callout's edge, the playground's run button. Never body text. |
| Dark gold | `#8A5A00` | Only if gold is ever needed as text on a light background. A new color, not in the logo. |
| Ink | `#16171C` | Text on light backgrounds, dark backgrounds. |
| Paper | `#F5F4EF` | Light backgrounds, text on dark backgrounds. |

Why these jobs:

- **Blue is safe for text.** Blue on white is 6.5:1 and white on blue is 6.5:1, so it works for
  links and for text on blue buttons. Blue on dark (`#4D78FF` on ink) is 4.6:1, just above the
  4.5:1 minimum for body text.
- **Gold isn't.** Gold on white is 3.1:1, below the 4.5:1 text minimum, which is why it's limited
  to highlights on light backgrounds. Dark gold (`#8A5A00`) is 5.9:1 on white. On dark
  backgrounds gold is fine for text: ink on gold is 9.8:1.
- **Grays.** Secondary text and dividers need one or two grays between ink and paper. Starlight's
  defaults can cover this until there's a reason to pick brand grays.

#### On the website

Starlight's theme takes three shades of the accent per theme, a pale tint, the main color and a
deep shade, set in `sites/website/src/styles/custom.css`. Proposed values:

| Starlight variable | Light theme | Dark theme |
| --- | --- | --- |
| `--sl-color-accent-low` | `#E3EAFC` | `#14224F` |
| `--sl-color-accent` | `#1F4FE0` | `#4D78FF` |
| `--sl-color-accent-high` | `#0F2A7A` | `#D4DEFF` |

The low and high shades are chosen to read against each other (10.7:1 in the light theme, 11.4:1
in the dark), since Starlight pairs them, for example as the background and text of the selected
sidebar item in the dark theme. Check each pairing on the built site rather than trusting the
ratios alone.

#### Deliberately left out

- A full scale of tints for every color (blue-100 to blue-900 and so on).
- A design-tokens file (`colors.json` or CSS variables shared across sites).

Nothing uses either yet. Add them when a second site or the editor theme needs the same values.

#### Questions for the review

- Does the blue accent look right in the website's dark theme, or does it need to be lighter
  for links?
- Does gold earn a place on the website at all, or is it better kept to the logo?
- Should NX code blocks and the VS Code theme use the two bracket colors for syntax highlighting,
  for example blue for tags and gold for expressions? That would tie the logo to how NX code looks.

### Using the logo

- **Minimum size.** 20 pixels tall for the logo, 16 pixels for the app icon.
- **Clear space.** Leave empty space on every side at least a quarter of the logo's height.
- **Icon backgrounds.** Put the app icon on ink or white only. On a blue or gold tile, one of the
  brackets has to lose its color and the two-bracket idea is lost.
- **Keep the colors where they are.** Blue on the `>`, gold on the `<`, the N neutral. Don't swap
  them, add a third color or fill the logo with a gradient.
- **Keep the shape.** Don't stretch, rotate or outline it, and don't retype the N in a font or
  replace the brackets with `>` and `<` characters: font brackets are smaller and sit at the
  wrong height.
- **One color when color isn't available.** Use the black or white version rather than a gray
  version of the colored logo.

### The shape

The logo is drawn on an 84-unit cap height. The numbers live at the top of `generate.mjs`:

| Setting | Value |
| --- | --- |
| Stroke width (the N's stems and each bracket arm) | 13 |
| Ends | Sharp: flat horizontal cuts, pointed tips where the brackets meet |
| Gap between the bracket tips | 4 |
| Width of the N | 66 |
| Space between the N and the `>` | 16 |
| Width of each bracket | 42 |
| App icon | The brackets fill 62% of the tile's width; corner radius 22% |

### Changing the logo

Change the numbers or colors in `generate.mjs`, never the generated files, then run from the
repository root:

```sh
pnpm install
pnpm --filter @nx-lang/branding generate
```

The script rewrites every file in this folder and the copies listed below. It renders PNGs with
[resvg](https://github.com/linebender/resvg) and sets the social card's text in
[Geist](https://vercel.com/font), whose two font files are kept in `fonts/`.

### Origin

The logo was designed in September 2026 by Bret Johnson working with Claude. The brief was a
modern mark for a declarative, markup-based language for building intelligent apps, positioned
as an alternative to JSX, TSX, XAML and SVG.

Four directions were explored: the bracket X, a monogram with the N's diagonal crossing an
accent stroke, the N drawn as a graph of connected nodes, and lowercase `nx` in a monospace font
with a blinking cursor. The bracket X was chosen because it is the only one that says both
"markup" and "NX" in one shape, and it holds up at favicon size.

Variations then settled the details:

- **Two colors on the X** make the two brackets readable even at 16 pixels, where the gap
  between them disappears.
- **Deep blue and gold** differ in lightness as well as hue, so the brackets stay distinct in
  grayscale and for color-blind viewers. Purple was avoided because it has become the default
  color of AI products.
- **Sharp ends** match the flat, formal feel of the colors, echo the `<` and `>` of code fonts,
  and stay crisp at small sizes. Round ends were the alternative.

The mark replaced a placeholder: a white `<X>` on a violet tile.
