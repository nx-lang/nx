## 11. An `if` with no `else` carries an implicit `else { }`

Supersedes the nullable reading that 3.x, 4.x and 9.2 implemented. The review found that a
conditional's *type* and what it *contributes* had become two notions, implemented four times, and
that RF1, RF2, RF7 and RF8 were each one engine getting the second wrong. Reading the missing
branch as `{}` leaves one notion: the conditional's type is a sequence, and the splice rule does
the rest.

- [x] 11.1 In `crates/nx-types/src/infer.rs`, type an `if` with no `else` as the join of its branch with `never[]`, and push `never[]` into a match's join when a path is uncovered; delete `open_conditional_contributions`, `open_conditional_type` and the arity-one open-conditional case in `check_content_binding`, leaving `item_contribution_of` reading only the item's own type; verify `cargo test -p nx-types` passes and `let v = { if c { 1 } }` infers `int[]`
- [x] 11.2 Make the join lift an item to a sequence — `join(T, U[])` is `join(T, U)[]` — when exactly one side is sequence-shaped, looking through `?`; verify an empty arm written out and a missing one infer the same type, an empty arm at an `A[]` content property no longer reports `found object[]`, and a nullable sequence beside a sequence joins to `string[]?` rather than `string[]?[]`
