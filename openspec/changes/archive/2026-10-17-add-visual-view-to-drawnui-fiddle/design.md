## Context

Paths under `nx/`, `src/`, `dev/` and `docs/` are in `~/src/DrawnUi.FiddleEngine`. Paths under
`packages/`, `crates/`, `sites/` and `specs/` are in this repository.

**The fiddle today** (`main`, clean; `nx-rust` and the earlier NX branches are merged):

- **Pins.** `@nx-lang/ir-runtime`, `language`, `monaco` and `sdk-wasm` are pinned at exactly `0.7.0`.
  `nx/rust/Cargo.toml` pins `nx-ir-runtime` and `nx-value` at `=0.7.0` and `drawnui` at
  `=0.1.0-preview.8`. `nx/nx-packages.mjs` and `nx/test/run.mjs` map the checkout's packages for
  `--nx ../nx`; neither knows `viewer` or `value-view`.
- **Editor.** The editor page (`Pages/FiddlePage.razor`, Blazor WebAssembly) holds one Monaco editor
  (BlazorMonaco 3.3.0, monaco-editor 0.52.2, `vs-dark`) in `.fiddle-code`, beside the canvas pane. It
  has one model, and `fiddleSetEditorLanguage` (`wwwroot/fiddle-react.js:508`) switches that model's
  language.
- **Language service.** NX registers through `fiddle-nx.js`. It loads `nx/nx-runtime.js` and then
  `nx.wasm`, then calls `NxDrawn.configure(monaco)`, which runs `registerNxLanguage` with Shiki's
  `dark-plus`. The language service is `@nx-lang/sdk-wasm`'s `createLanguageService`, running on the
  main thread with `documents: [catalog]` and `implicitImports: ['drawnui.nx']` (`nx/src/runtime.ts`).
- **Page rule.** The page is language-agnostic (fiddle `AGENTS.md`, "Rules"). Language-specific
  behavior lives in `IFiddleLanguage` and its script.
- **Catalog.** `nx/catalog/drawnui.nx` is generated by `nx/generate-catalog.mjs` from
  drawnui-react 0.1.0-preview.17. It declares 11 abstract bases (`DrawnNode`, `SkiaControl`,
  `SkiaLayoutBase`, `SkiaLabelBase`, `SkiaImageBase`, `SkiaShapeBase`, `SkiaToggle` and others) and
  35 concrete external components. Colors are plain `string`, and there are no visualizer
  declarations.
- **Shares.** A share stores an NX IR image. `fiddle-nx.js` has `CURRENT_SCHEMA = 5` and
  `OLD_SCHEMAS = { 4: '0.3' }`, and `nx/retired/README.md` gives the procedure for a schema change. The
  page's `NxCurrentVersion` is a stale `"0.4"`.

**NX since v0.7.0** (181 commits, unreleased):

- `@nx-lang/viewer` and `<nx-viewer>` (spec `viewer`).
- The `sourceTree` query with `visualizers: { modules }` (spec `source-tree`).
- Visualizer declarations and `@nx/visualizer` (specs `visualizer-declarations` and
  `visualizer-library`).
- The playground's Visual and Source switch (`sites/playground/src/reading/`,
  `editor/positions.ts`).
- IR schema 6.

The viewer follows the page's `color-scheme`. It takes `colors` from `@nx-lang/value-view`'s
`colorize`, an `icons` function, `folded` and `selection`, and fires `nx-select` and `nx-fold`. A text
alias named `uitext` reads as prose. A `ValueVisualizer` with `format=color` gives a swatch.

## Goals / Non-Goals

**Goals:**

- The fiddle's Visual view behaves as the playground's does, through the fiddle's own editor and
  language service, with no NX code copied that NX could export instead.
- The engine gains one generic, small hook, not NX-specific branches in the page.
- The catalog reads well with hand-written visualizers. They stay correct across catalog
  regenerations because tests catch drift.

**Non-Goals:**

- Moving the fiddle's language service into a worker.
- Changing the playground.
- A light theme for the fiddle.
- Per-visitor persistence of the chosen view across page loads.

## Decisions

### 1. Build against the checkout, release v0.8.0, then repin

As in `update-fiddle-to-latest-nx` and `add-nx-rust-to-drawnui-fiddle`, the fiddle work is done with
`--nx ../nx` on a fiddle branch. Before that, `nx-packages.mjs` and `test/run.mjs` learn `viewer` and
`value-view`. The Rust player names the crates by path for the duration, following the
`fiddle-nx-rust-language` rule that this state is never merged.

Fixes the integration finds in this repository land before the tag. Then v0.8.0 is cut by the
ordinary runbook (`docs/deployment.md`), with a changelog section. The fiddle then moves to
`0.8.0` everywhere and runs every suite without `--nx`.

*Alternative:* release first, then integrate. Rejected, because integration is where viewer and
host-module API problems show, and a published version is permanent.

### 2. The engine's hook: `HasVisualView` plus a `visual` object in the registration

- **C# side.** `IFiddleLanguage` gains a default member `bool HasVisualView => false`. `NxLanguage`
  and `NxRustLanguage` return true.
- **The page.** `FiddlePage.razor` renders a thin bar at the top of `.fiddle-code` only when the
  language has a visual view. The bar holds a segmented Visual | Source control, plus Collapse all and
  Expand all while Visual shows. Below the bar sit two siblings: the editor, and a `.fiddle-visual`
  host div, toggled with `hidden`, as the canvas surfaces are.
- **JS side.** A language's registration in `fiddleReactRegisterLanguage` may carry
  `visual: { show(host, editor), hide(editor), collapseAll(), expandAll(), reset() }`.
  `fiddle-react.js` gains `fiddleShowEditorView(view)` and `fiddleEditorViewCommand(name)`, which
  call the current language's `visual`. The page calls them when the switch changes, and calls
  `reset` when a preset or share loads or the language changes.
- **State.** The page keeps which view shows (Visual by default). The view survives a switch
  between `nx` and `nx-rust`, because both register the same `visual` (`fiddle-nx-rust.js` reuses
  `fiddle-nx.js`'s).

*Alternative:* a generic "extra editor tabs" list on the contract. Rejected as more than one view
needs; the hook can grow when a second language wants one.

*Alternative:* an `<iframe>` or a Blazor component for the reading. Rejected, because `<nx-viewer>` is
a framework-free custom element that drops into a div.

### 3. The reading lives in `nx/src/visual.ts`, inside `nx-runtime.js`

`NxDrawn.visual` is created lazily by `configure`. It does the following:

- Asks `service.sourceTree({ documents, uri, visualizers: { modules: ['drawnui-visualizers.nx'] } })`
  of the existing main-thread service: at once on `show` when the editor's text is not the text
  it last read, then 350 ms after the model's last change while shown. It aborts the query a newer
  edit supersedes, and sets `stale` while waiting. With the text unchanged it neither asks nor
  redraws, so the reading stays where the visitor left it.
- Sets `text`, `tree`, `folded`, `selection`, `icons`, and `colors` from `colorize(highlighter, text,
  { light: 'dark-plus', dark: 'dark-plus' })`, with the highlighter `@nx-lang/value-view`'s
  `loadHighlighter` gives it on the first show, as the playground's reading does (the bundle keeps
  only `dark-plus`). `@nx-lang/monaco` keeps the one `registerNxLanguage` builds to itself, so this
  is a second Shiki highlighter, with its own copy of the regex engine and the NX grammar; sharing
  one would take a new `@nx-lang/monaco` export, which can follow in a later release.
- Keeps `folded` from `nx-fold` and the selection from `nx-select`. `reset()` sets `folded =
  undefined` and clears the selection.
- On a visitor's `show`, selects `keyAtRange` of the editor's selection (the node at the cursor when
  it is empty) and scrolls the reading with `scrollToKey`. On a visitor's `hide`, selects the
  selected node's text (`rangeOfKey`) with the cursor at its start, scrolls the editor to match, and
  focuses it. Either way the place carried is the selection when it was in view, and otherwise the
  first node starting in view (`keyAtTop` in the reading, the first line that starts a node in the
  editor), set as far below the top as it was. A view left as the switch placed it leaves the other
  where it was, so a round trip with nothing moved comes back exactly.

The page keeps the editor and the host div in one grid cell under the bar, the one not shown
`visibility: hidden` rather than `display: none`. Each then keeps its size and scroll position, and
whichever is being left can still be measured when the switch carries its place across. With
`display: none` the reading's scroll was lost on every switch and neither view could be measured
once hidden.

*Alternative:* track each view's place on every scroll and remember it for the switch. Rejected:
more code, and the editor still relaid itself out at no size while hidden.

*Alternative:* put the cursor at the node's start without a selection, as before. Rejected, after
the visitor asked for the same text to be selected: it shows which text the reading's node is, and
copy, cut and delete act on the element. Typing replaces the selection, as in any editor after a
go-to, and undo brings it back.

The host div sets `color-scheme: dark`, `--nx-viewer-source-font-family` to the editor's font,
`--nx-viewer-prose-font-family` to the page's font, and the selection and hover colors from the
editor theme.

The selection helpers (`keyAtRange`, the node holding an editor selection or cursor, and
`rangeOfKey`, a node's start and end as offsets; first written as `keyAtOffset` and `offsetOfKey`,
and widened to ranges when the fiddle came to carry a whole selection) are needed by both the
playground and the fiddle. They move from
`sites/playground/src/reading/selection.ts` into `@nx-lang/viewer` as exports, with their tests,
before the release, and the playground imports them. They work on the tree's UTF-16 ranges, so no
byte conversion is needed. The rest of `editor/positions.ts` serves the playground's value view and
stays.

*Alternative:* copy them into the fiddle, as the instance tree once was. Rejected, because they are
host-independent and small, and a second copy is what the release is the moment to avoid.

### 4. Icons: the whole Lucide set in a separate lazy bundle

`dev/build-nx-runtime.mjs` builds `nx/nx-icons.js`, an IIFE that publishes
`window.NxIcons = { icons, createElement }` from `lucide`, about 450 KB raw. `visual.ts` loads it by
script tag on the first `show` and memoizes drawn icons by name, as the playground's `loadIcons` does.

*Alternative:* only the icons the visualizer module names. Rejected, because a snippet's own
visualizers may name any Lucide icon. The lazy load already keeps the cost off pages that never
show Visual.

### 5. Visualizers are a hand-written host module, not generated into the catalog

`nx/visualizers.nx` (identity `drawnui-visualizers.nx`) imports `@nx/visualizer` and sees the
catalog through the service's implicit import. It is bundled as text into `nx-runtime.js` beside
`drawnui.nx` and passed to `createLanguageService` as a second document. The compile path never sees
it, so shares and the catalog image are unaffected.

Generation stays mechanical, and presentation is curated by hand. Host modules are what the
visualizer spec offers for exactly this ("a host module overrides a library"). Inheritance lets most
of the presentation sit on a handful of bases.

*Alternative:* the generator emits visualizer declarations into `drawnui.nx` from a JSON table.
Rejected for three reasons: a second hand-kept table, a catalog that imports `@nx/visualizer`, and
a catalog image whose fingerprint changes with every icon tweak.

### 6. `Color` and `uitext` are aliases the generator writes

- **`Color`.** `generate-catalog.mjs` declares `export type Color = string` and uses it for every
  `string` property whose name ends in `Color` (49 today; `ClipBackgroundColor: boolean` is untouched).
- **`uitext`.** It declares `export type uitext = string` and uses it for the properties in a short
  list kept in the generator: `Text`, `PlaceholderText`, and others found by reading the catalog.
  `uitext` is the name the viewer reads as prose.
- **Effect on checking.** Aliases are transparent to type checking, so no snippet's diagnostics
  change. Hover and completion show the alias names, which says more than `string`.
- **Records.** Record fields such as `SkiaShadow.Color` take the alias too. A record is read like
  any element.

*Alternative:* `PropertyVisualizer property=X format=color` per property in the host module. Rejected
because it means about 30 entries kept by hand, and no help in hover. The visualizer module still
declares `visualizer Color`, so the format decision stays in presentation.

### 7. Tests in `nx/test/visualizers.test.ts`

The suite runs with `test:nx`, so `npm run runtime` runs it too. It:

1. Analyzes `visualizers.nx` with the catalog and requires no diagnostics.
2. Asks a source tree of a snippet constructing every concrete catalog component, with the module
   named, and requires a non-empty `icon` on every component's entry.
3. Requires every `icon="…"` in the module to be a Lucide export.
4. Checks the three scenario readings of `fiddle-nx-catalog-visualizers` on the tree: a title, an id,
   and a color format.

A further test compiles every preset with and without the second document and compares the share
modules.

### 8. Old shares: freeze `s5`, read the current version from the runtime

Before the pins move, the served `wwwroot/nx/nx-runtime.js` built from 0.7.0 is copied to
`nx/retired/s5/nx-runtime.js`. `fiddle-nx.js` then sets `CURRENT_SCHEMA = 6` and
`OLD_SCHEMAS = { 4: '0.3', 5: '0.7' }`, and the README's list gains `s5`.

`NxDrawn` exposes `nxVersion` (from the `@nx-lang/sdk-wasm` package version, written into the bundle
at build). The page's note uses it in place of `NxCurrentVersion`.

`nx-rust` shares get no retired player. It would be another 6.4 MB per schema, for shares at most a
week old. The player's existing schema refusal stands.

### 9. An element's layout follows the pane, not the source's line breaks

Testing the fiddle showed that a rule based on the source's line breaks reads poorly. The UI preset
wraps long tags several attributes to a line, so which attributes landed on a group's header and which
got rows depended on where the author happened to wrap. The fix in task 9.1 gave each attribute after
the first line a row; that read better, but it still split one element's properties between its header
and its rows.

The reading now decides from the pane's width:

- **A line** when the element holds no elements and its properties fit after its name on one line.
- **A group with a row to each property** when they do not fit.
- **A group with its properties on its header** when it holds elements and they fit there.
- **One property, or none,** stays a line, wrapping if it must; a row would not shorten it.
- **A property's element value** (`Padding=<Thickness …/>`) stays on its row when it fits there, so a
  short value does not stack a row under another row; one too long for its row, as an
  `appearance=<ImmersiveAppearance …/>` that would wrap its `name=value` pairs down the value column,
  reads as a group under the property's name. It is measured where a group shows it, on its
  holder's header or row: one on a line wraps with that line, and a holder that shows one property
  stays a line, while a group's header holding one element value is measured, so it gets a row. On a header that does not fit it is not where it will be, so it is measured again
  once the header's properties have rows; each pass settles one level of values, while what a group
  holds under its header is measured in the same pass as the header.

This keeps a run of short siblings (a column of labels) as one line each, which scans easily, and
gives rows only to elements that would otherwise wrap, where wrapped `name=value` pairs are hard to
read.

"Fits" needs layout, so the element measures: it draws every element as a line or a header, collects
the ones whose line or header takes more than one line, or whose folded header, which is cut rather
than wrapped, runs past its line (the `fit-check` units), and draws again with
those as rows (`SourceLayout.wrapped`), up to six passes, before the browser paints. It measures again
when the body's width changes (a `ResizeObserver`), once the width has held for 120 ms so a dragged
divider costs one measure and not one a frame, and when fonts finish loading, keeping the node at the
top where it was. A reading hidden by `visibility: hidden`, as the fiddle's view not shown is, still
measures, so the place it gives the editor on a switch is where it would show. Hidden or detached it measures nothing and reads everything as lines and headers,
and the size it takes when shown draws it again. Tests fake the measure, since jsdom lays nothing out.

Alternatives tried on a branch, with a switch in the fiddle:
- **Follow the source's lines** (the rule before): rejected for the reason above.
- **A reader's choice of `flow` or `sheet`**: `flow` wraps every busy element into noisy runs of
  pairs, and `sheet` spends a row on every property of every short element. Each was right only for
  some elements, which is what the pane-width rule picks.
- **Estimating width from character counts**: rejected because the prose font, icons and swatches make
  counts approximate, while measuring is exact.

## Risks / Trade-offs

- **Host visualizer modules are new and untested outside this repository's own tests** → Exercise them
  first, in task 2. If `createLanguageService` cannot take a module the program does not import, or the
  implicit import does not reach it, fix that in `sdk-wasm` before the release.
- **`uitext` is recognized by alias name across a module boundary** → The viewer may check the alias by
  its declaring module or by name. Verify with the catalog's alias in task 2, and fix in the viewer if
  only same-module aliases work.
- **The main-thread service now also answers source trees** → A tree for a 200-line preset should take
  a few milliseconds. Measure on the largest preset. If a query exceeds about 30 ms, ask only while
  Visual shows (already the rule) and lengthen the debounce. Moving to a worker is out of scope.
- **The catalog image changes** (its fingerprint hashes the source, and the aliases change the source)
  → Shares link by name and catalog version. The existing "survives a regenerated catalog" scenario
  covers this. Verify that a share made before the regeneration still plays.
- **Monaco 0.52.2 vs. the viewer** → The viewer does not depend on Monaco. The selection glue uses only
  `setPosition`, `revealPositionInCenterIfOutsideViewport` and `getPosition`, which 0.52 has.
- **The private drawfiddle.com host** → It loads the engine's scripts and `nx-runtime.js`, so the
  switch comes with them. It must also serve `nx/nx-icons.js` and `nx/s5/`, which the runtime build
  writes into the target web root. Tell its maintainer in the PR.
- **Visual as the default in an editing tool** → It matches the playground, and C# and TSX are
  unaffected. If visitors find it in the way, flipping the default is a one-line change.

## Migration Plan

1. In NX: move the position and selection helpers into `@nx-lang/viewer`, and make any fixes the
   fiddle work finds.
2. In the fiddle: on a branch, freeze `s5` from the 0.7.0 build first, then do the integration
   against `--nx ../nx`.
3. In NX: add the changelog section, then tag and publish v0.8.0.
4. In the fiddle: repin, then run every suite without `--nx`. That covers `test:nx`,
   `test:nx:rust`, `browser-check.mjs` and a new Visual browser check. Then open the PR.

Rollback: the fiddle PR is one revert. The `s5` runtime and the pins move together, so reverting
leaves 0.7.0 serving schema 5 as before.
